# 月伤实现与验证记录

日期：2026-10-25。版本：`0.4.10-fix.2+1.21.8+lts`，Java 21，Minecraft 1.21.8 Fabric，Polymer 0.13.8。代码位于 `codex/fabric-1.21.8-fixes`，与此前音乐修复一起交付到用户 fork，不创建 PR。

## 已实现

- [当前规则](current-rules.md)中的武器档位、日夜倍率、滚动60 tick窗口、玩家与非玩家分流、第五次替换、真伤最后封顶、铂金四件普通补伤抗性。
- 连击与冷却绑定具体武器，允许转交继承及多武器轮换；PvP连击区分目标，PvE跨怪累计；玩家6 tick、非玩家1 tick、玩家真伤30 tick。
- 使用Player主目标和Mob标准主目标近战入口；一次原始攻击一次月伤，不从火焰、弹幕、投掷或扫击副目标泛触发。末影龙部位解析到本体跟踪，原伤害仍先经过部位/阶段逻辑。
- 普通补伤加入本次正常伤害；真伤在同一次原生减伤和黄心抵扣之后加入，不另打一笔hurt，不清零目标公共lastHurt。低血量不再跳过真伤，死亡/图腾仍留在原生流程中处理。
- 完全格挡与原伤害失败不提交计数；嵌套攻击暂停月伤效果，目标生命周期清理延后至在途命中提交后；到期和停服清理短期状态。
- 月伤策划说明独立存放于本目录；19个既有源码文件中的55条策划/玩法参数注释已迁至[注释归档](../source-notes/README.md)，迁移未改变这些文件的可执行token。

## 追加：隔离专服与真实伤害探针

2026-10-25 用户授权后，使用一套独立临时目录搭建Minecraft 1.21.8 Fabric专服，只监听127.0.0.1、系统分配端口，离线白名单模式，不加载原服务器存档。运行修复版 `fix.2` 已编译代码；完整未改素材复用此前本地完整构建，当前元数据和Mixin配置来自 `fix.2`。自音乐修复提交以来，资源目录只改了本次叠加的Mixin配置。

实际加载61个原组件和1个临时探针组件。专服达到 `Done`，Polymer完整资源包生成成功。真实ServerLevel中，用原生Player的临时子类调用真正的 `Player.attack`，不直接调用生产helper，完成以下12个报告用例：

1. PvE真伤绕过护甲、抗性与吸收生命，普通伤害正常消耗黄心。
2. PvP普通补伤及同tick不重复触发。
3. 5 tick时不补月伤，但普通攻击仍有效。
4. 恰好6 tick允许月伤。
5. 玩家第五次真伤封顶2 HP且绕过黄心。
6. 铁剑第五次仍是普通伤害。
7. 同一ItemStack从一个测试持有者转给另一个后继承第五次层数。
8. 同一武器的不同玩家目标分别统计层数。
9. 同一武器跨玩家目标共享真伤冷却。
10. 冷却中的第五次回退普通月伤、清层，冷却到期后恢复真伤。
11. 目标生命低于2 HP时真伤可以致死，原生图腾救回后没有第二段追杀。
12. 完整盾挡不受月伤，也不占用该武器月伤间隔。

最终结果：`passed=12 failed=0`。第一次探针遗漏头部朝向，盾牌用例未通过；官方格挡逻辑使用getYHeadRot，补齐测试角色头部朝向后，在同一套临时服中正常重启复核全部通过。**生产代码未因此修改。** 最终运行日志没有ERROR或探针失败，离线模式、开发版与未翻译标签提示不作为错误。

边界：这些演员不是联网ServerPlayer，不加入玩家列表，未模拟客户端丢弃拾取或多人压力。因此它证明实际原生攻击/伤害链中的上述路径，不代表联网客户端、真实丢弃拾取、第三方保护模组或TPS压测完成。

正常执行stop，所有维度保存完成，进程退出码0。随后删除整套临时目录约126 MiB，包含世界、配置、日志、资源包、缓存下载、探针jar/源码/编译物、启动脚本与类路径文件；额外路径标记也已删除。确认测试Java与控制进程均无残留，仓库没有run目录。仅保留本Markdown摘要，没有保存原始测试日志或测试服副本。测试期间生产源码对应提交770c8526，后续本次仅更新验证文档。

## 在服务器复现

在JDK 21环境中，从仓库根目录运行：

```sh
bash gradlew check --max-workers=2
python3 tools/test_music_lifecycle.py
python3 tools/test_music_sessions.py
python3 docs/gameplay/source-notes/verify_comment_migration.py
```

若使用非默认Gradle缓存，给Python会话测试设置对应的 `GRADLE_USER_HOME`。首次构建需要下载依赖。需要完整发布jar时运行：

```sh
bash gradlew build --max-workers=2
```

Gradle原配置最大堆3 GB；没有升级Gradle/Java版本。初次编译阶段不创建测试服，后续获授权的隔离专服使用2 GB最大堆，现已彻底清理。生产替换仍要求原有外置依赖，其中Resource Config API使用1.21.8-3.7.3。

## 验证边界

- 状态机和上下文为隔离验证，Knot证明真实变换位置；追加原生攻击探针已在真实ServerLevel验证盾牌、图腾和低血致死路径，但不等于联网玩家实战。
- 未进行原存档战斗、TPS压测或第三方领地/保护模组兼容验收；原版伤害拒绝路径保留，但不能凭编译保证所有其他模组组合。
- 武器转交有纯状态验证和两个原生Player演员间同一ItemStack交接验证；真实丢弃拾取、修复和外部复制仍需进服验证。当前会识别同时仍在上个持有者装备/背包中的同ID复制品并拆分身份；原物在箱子、掉落实体或离线持有者处时，外部命令/模组强制复制持久身份无法全面区分于合法转交，不宣称彻底防复制。
- NPC标准近战使用同类入口，非标准自定义伤害不会自动加入月伤；Mob对玩家的普通伤害仍可受原版难度缩放，与玩家对玩家静态算表不同。
- 允许多武器独立冷却，因此旧的每攻击者固定频率上限不适用；性能应按活跃武器和实际有效攻击输入评估。

独立审查已修复末影龙部位遗漏、嵌套目标清理使在途计数失效、干净构建映射元数据依赖三项问题；修正后没有剩余已确认的阻断项。
