# 月伤实现与验证记录

日期：2026-10-25。版本：`0.4.10-fix.2+1.21.8+lts`，Java 21，Minecraft 1.21.8 Fabric，Polymer 0.13.8。代码位于 `codex/fabric-1.21.8-fixes`，与此前音乐修复一起交付到用户 fork，不创建 PR。

## 已实现

- [当前规则](current-rules.md)中的武器档位、日夜倍率、滚动60 tick窗口、玩家与非玩家分流、第五次替换、真伤最后封顶、铂金四件普通补伤抗性。
- 连击与冷却绑定具体武器，允许转交继承及多武器轮换；PvP连击区分目标，PvE跨怪累计；玩家6 tick、非玩家1 tick、玩家真伤30 tick。
- 使用Player主目标和Mob标准主目标近战入口；一次原始攻击一次月伤，不从火焰、弹幕、投掷或扫击副目标泛触发。末影龙部位解析到本体跟踪，原伤害仍先经过部位/阶段逻辑。
- 普通补伤加入本次正常伤害；真伤在同一次原生减伤和黄心抵扣之后加入，不另打一笔hurt，不清零目标公共lastHurt。低血量不再跳过真伤，死亡/图腾仍留在原生流程中处理。
- 完全格挡与原伤害失败不提交计数；嵌套攻击暂停月伤效果，目标生命周期清理延后至在途命中提交后；到期和停服清理短期状态。
- 月伤策划说明独立存放于本目录；19个既有源码文件中的55条策划/玩法参数注释已迁至[注释归档](../source-notes/README.md)，迁移未改变这些文件的可执行token。

测试先移开旧的Loom映射classpath文件，再由明确依赖的 `generateRemapClasspath` 任务重新生成，避免依赖历史测试服缓存。Knot测试只初始化加载器和变换类，不调用服务器主方法；已确认未生成世界、server.properties、EULA，仓库也没有重新创建run目录。

本地项目目录出现过增量缓存和文件读写超时。最终验证将构建输出放到临时目录，并在临时init脚本中只复制模组元数据、Mixin配置和access widener，跳过未修改素材；**正式构建脚本没有排除素材**。因此本轮确认源码编译、测试和变换通过，不宣称已完成完整资源包打包或服务器启动验收。

## 在服务器复现

在JDK 21环境中，从仓库根目录运行：

```sh
bash gradlew check --max-workers=2
python3 tools/test_music_lifecycle.py
python3 tools/test_music_sessions.py
python3 docs/gameplay/source-notes/verify_comment_migration.py
```

若使用非默认Gradle缓存，给Python会话测试设置对应的 `GRADLE_USER_HOME`。首次构建需要下载依赖。需要完整发布jar时运行：

```sh
bash gradlew build --max-workers=2
```

Gradle原配置最大堆3 GB；本次没有升级Gradle/Java版本，也没有为编译创建测试服。生产替换仍要求原有外置依赖，其中Resource Config API使用1.21.8-3.7.3。

## 验证边界

- 状态机测试和上下文测试是针对性隔离验证；真实Knot预检证明目标类及变量注入位置，不等于有人进服完成盾牌、图腾和死亡全过程的实战测试。
- 未进行原存档战斗、TPS压测或第三方领地/保护模组兼容验收；原版伤害拒绝路径保留，但不能凭编译保证所有其他模组组合。
- 武器转交的状态归属有纯状态验证；实际物品交接、修复和外部复制还需进服验证。当前会识别同时仍在上个持有者装备/背包中的同ID复制品并拆分身份；原物在箱子、掉落实体或离线持有者处时，外部命令/模组强制复制持久身份无法全面区分于合法转交，不宣称彻底防复制。
- NPC标准近战使用同类入口，非标准自定义伤害不会自动加入月伤；Mob对玩家的普通伤害仍可受原版难度缩放，与玩家对玩家静态算表不同。
- 允许多武器独立冷却，因此旧的每攻击者固定频率上限不适用；性能应按活跃武器和实际有效攻击输入评估。

独立审查已修复末影龙部位遗漏、嵌套目标清理使在途计数失效、干净构建映射元数据依赖三项问题；修正后没有剩余已确认的阻断项。
