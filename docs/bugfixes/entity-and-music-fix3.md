# 扫帚、人偶与音乐文件修复

日期：2026-10-25。版本：`0.4.10-fix.3+1.21.8+lts`，Java 21，Minecraft 1.21.8 Fabric。

## 扫帚

生物蛋创建的扫帚没有绑定物品，`itemWrapper` 为空。原 `getName()` 回退到原版取名，而原 `getCustomName()` 又调用 `getName()`，形成无限递归。在真实 Minecraft 类上调用空扫帚取名已复现 `StackOverflowError`。

删除递归的 `getCustomName()` 覆盖，恢复原版自定义名存取；已绑定物品的扫帚仍以物品名称显示。没有改变骑乘、耐久或掉落规则。

没有旧服务器异常堆栈，故只能确认这一条实际存在的崩溃路径；尚未在联网服务器完成“生物蛋生成后攻击”的完整验收。

## 坐姿伙伴死亡

原 `SEATED` 分支直接返回，不调用父类 `tick()`，使已死亡实体无法推进原版死亡计时。新增死亡分支：先脱离骑乘、删除座椅和清理座椅引用，然后交由原版推进死亡与移除。死亡更新不再创建座椅。

存档重载后若只剩 `SeatUUID`，通过当前 ServerLevel 已加载实体索引恢复并清理座椅，不强制加载其他区块；空值、旧的 `null` 字符串或无效 UUID 不阻断死亡清理。已死亡、已加载的旧坐姿尸体也会进入该路径。存活时坐下/站起的行为保留。

没有更改死亡掉落、角色存档、装备或角色卡规则。

## 删除音乐文件

用户反馈来自旧版本，目前没有对应崩溃报告。fix.2 已有“文件不存在/解析失败则不创建播放器”保护。新增会话回归确认：延迟启动前删除、播放时删除后断电/通电、重载后仍选择已删除文件，均不会启动空播放器或抛出异常。已加载歌曲在内存中继续播放，断电后停止，再次通电时因文件缺失保持静默。

另确认 NBS 解码器没有关闭输入流。修复为 try-with-resources，成功、截断文件和异常路径都会释放文件句柄，避免长期累积句柄及 Windows 删除文件时被打开的流阻挡。该问题已确认存在，但没有将它认定为旧崩溃的唯一原因。

## 验证

- 新增扫帚取名测试：3组，在真实 Minecraft 类型上执行；修复前栈溢出，修复后通过。实体使用最小同步数据初始化，不启动世界，也不模拟完整受击流程。
- 人偶生命周期测试：5组，直接提取生产 tick/removeSeat 方法体运行，外部世界和父类死亡计时使用窄替身；修复前坐姿尸体不推进计时，修复后通过。覆盖旧尸体、已有/已保存/缺失座椅及存活坐站切换；不等同于完整游戏内角色卡验收。
- NBS 流/文件测试：3组，使用真实解码器；修复前读取流未关闭，修复后通过。加入真实临时文件解码后立即删除测试；本机为 macOS，Windows 构建也会运行该测试。
- 音乐会话：10项、播放器/任务生命周期：9项，全部通过；会话测试使用外部 API 替身，新增3项删除文件场景在原 fix.2 已通过。
- Gradle `check`：通过，21秒，包含现有月伤状态、武器档位、真实 Knot/Mixin 变换和键盘 Dialog 检查。
- 未搭建或保留测试服务器。测试临时音乐文件和生命周期测试目录由测试自行删除。
