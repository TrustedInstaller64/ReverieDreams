# Fabric 1.21.8 修复版

基线：上游 `1.21.6/8` 分支 `b70aacb6a9fed5200d8834531b87772483521f68`，模组 0.4.10 LTS。目标为 Minecraft 1.21.8 Fabric、Java 21。保留原命名、代码布局、Nota 的制表符风格及原有注册方式。

## 修改内容

- 音乐盒不会为检查音乐方块而重新加载已经卸载的区块。
- 同位置使用一个待启动/播放会话；停止、替换、断线、实体失效、区块/世界卸载及停服时取消任务、销毁播放器。
- 旧方块实体和旧回调按实例身份清理，不会删掉同坐标的新会话。
- DelayedTask 在调用前出队；失败任务不重放，失败不阻止其他任务；重复任务有稳定的取消身份。
- Nota 销毁播放器时取消 Timer、清理监听与注册；后台计时器只提交有界的服务器线程任务。
- 文件列表 Stream 正确关闭、歌曲按名称排序；路径限定在配置音乐目录。损坏文件在同一会话内只解析一次，避免每 tick I/O/日志。
- 键盘使用原版 Dialog：歌曲列表、每页 20 首、当前选择标记、上一/下一页、播放与停止。按钮重新验证当前手持物品，文件名经 Brigadier 正确转义。

冈格尼尔文件及模型保持 LTS 原实现，未引入新版长矛或冲刺体系。月伤机制也未修改，实际效果和受伤保护分析见 `moon-damage-lts.md`。Balm 等其他模组按确认范围留待独立修复。

## 键盘使用

把 NBS 文件放入服务器工作目录的 `config/reverie_dreams/nota/`。持键盘蹲下右键打开列表，点击歌曲进行选择，点击播放开始演奏。普通右键仍可演奏已选曲目，原有 NPC 合奏入口保留。主手、副手均支持。

界面只操作当前玩家对应手中的键盘；期间移走物品后按钮不会继续修改物品。歌曲被删除后重新点击会提示选择仍存在的歌曲。

音乐盒坏曲目采用一次失败锁存策略：修好/补回同名文件后，需要切换红石、重新切歌或重载音乐盒以明确重试；不会在持续供电时每 tick 重读坏文件。

## 外置依赖与启动核验

原工程自带 Resource Config API `1.21.7-3.7.3` 的元数据排除了 1.21.8，真实启动时已被加载器拒绝。现改用官方 `1.21.8-3.7.3`，与原服务器 Spark 记录一致；该依赖 SHA-1 为 `ece8863f0941d60e79b72c3f291e22518c7ca897`。它仍是外置依赖，不是悄悄嵌入另一个副本。

本地新建的专服测试使用 Java 21、Fabric Loader 0.16.14、Fabric API 0.136.1+1.21.8，共加载 61 个组件，已达到 Done、生成资源包，并接受 stop 命令保存所有维度后退出。该验证只使用新测试世界，没有接触原服务器或原存档，不等价于原场景长时间内存稳定性验收。

测试服使用超平坦世界时，空的生成器设置曾记录 `No key layers in MapLike[{}]`，随后恢复默认设置并完成启动。因此本次结论是启动、加载与正常停服通过，不是日志完全无错误。

## 构建与验证

在 Java 21 环境使用仓库自带 wrapper：

```sh
./gradlew build
python3 tools/test_music_lifecycle.py
python3 tools/test_music_sessions.py
```

Windows 使用 `gradlew.bat build`；Python 测试需要 Python 3 和 JDK（JAVA_HOME 或 PATH 中的 javac/java）。`test_music_sessions.py` 复用 Gradle 已解析的 Lombok，外置 Gradle 缓存时设置 GRADLE_USER_HOME。

构建的 check 包含 `testMusicDialog`：使用真实 1.21.8 Dialog 类型验证空列表、分页、选中标记与特殊文件名的命令往返。Python 两组测试运行真实的待测实现，分别为生命周期和会话调度提供窄外部 API 替身；不把它们称作完整游戏服复现。

按最终交付要求，本次交付源码与编译验证记录，不另行打包或分发 jar。上述构建验证已通过，无需为交付重复构建。

客户端点击表现、实际音频节奏，以及原存档长时间运行后的对象数量与 GC 稳定性，需要对应实机验证。任务合并刻意限制卡顿期间的待执行工作，不承诺严重卡顿时音乐仍保持原墙钟节奏。
